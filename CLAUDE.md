# Galaxy — памятка для будущих сессий

Карта знакомств в виде звёздного неба: каждый участник — светящаяся звезда,
знакомство — линия, чем больше связей, тем ближе к центру. Живёт как Telegram
Mini App по адресу <https://kvadratnikitosa.ru/galaxy>.

Исходное техническое задание — `SPEC.md`. Оно остаётся нормативным документом,
но по ходу работы часть решений заказчик изменил; все расхождения перечислены
ниже в разделе «Отступления от ТЗ» и продублированы комментариями прямо в коде.

## Как устроено

| Слой | Что использовано |
| --- | --- |
| Клиент | React 18 + TypeScript, Vite, zustand; рендер — Canvas 2D вручную |
| Сервер | Node 22 + Express 4 + TypeScript, Prisma, PostgreSQL 16 |
| Процесс | pm2, один инстанс `galaxy` на порту 3005 |
| Веб-сервер | nginx проксирует `/galaxy/` на Node; статику раздаёт сам Node |

Контейнеров нет. Запрещены и не используются: Next.js, Fastify, NestJS, Redis,
очереди, GraphQL, **zod и любые библиотеки схемной валидации**.

## Вещи, которые нельзя ломать

1. **Подпуть `/galaxy`.** Задан один раз в `shared/config.ts` и протянут через
   `base` в Vite, роутер клиента, API-клиент, монтирование express-роутера,
   путь сессионной куки, адрес вебхука и раздачу аватарок. Захардкоженных
   `/api/...` в коде быть не должно: они уведут в соседнее приложение домена.
2. **`proxy_pass` в nginx без завершающего слеша.** Со слешем nginx срежет
   префикс, и все маршруты отдадут 404.
3. **Ровно один инстанс pm2.** Таймер пересчёта раскладки и воркер рассылки
   держат состояние в памяти процесса.
4. **Каталог аватарок вне `dist`** (`/root/dev/galaxy/avatars`), иначе
   `rsync --delete` вычистит его при каждом деплое. То же про `.env`
   и `snapshots/`.
5. **Личность запроса берётся только из подписанной куки.** Клиентские id
   в теле запроса — это всегда цель действия, никогда не тот, кто действует.
6. **Прогретые аватарки и ассеты кешируются навсегда, `index.html` — никогда.**

## Раскладка

Ядро продукта. Считается на сервере, координаты пишутся в `User.x/y`,
клиент их только анимирует.

Порядок: центральность → начальные позиции → силовая симуляция → нормализация
→ выравнивание по Прокрусту → запись в БД.

- `shared/layout/centrality.ts` — степень + собственная центральность
  (степенной метод), затем ранговая шкала.
- `shared/layout/simulate.ts` — три силы (радиальная привязка к целевой орбите,
  кулоновское отталкивание по всем парам, пружины на рёбрах), полуявный Эйлер
  с охлаждением, жёсткое разведение пересечений, снятие сноса центра масс.
- `shared/layout/normalize.ts` — центрирование по массам, масштаб по 95-му
  процентилю.
- `shared/layout/procrustes.ts` — поворот и отражение к предыдущей раскладке,
  чтобы небо не переворачивалось.
- `shared/layout/params.ts` — **все коэффициенты здесь**, с комментариями.

**Два места выполнения.** На сервере (`server/src/layout/pool.ts`) расчёт идёт
в `worker_thread`: полтора-два десятка сотен узлов занимают секунду-две, и без
отдельного потока сервис на это время замолкал бы. На клиенте
(`web/src/layout/worker.ts`) та же математика крутится в Web Worker сразу после
действия человека — чтобы он увидел результат немедленно, не дожидаясь сервера.

**Клиентский расчёт — это предположение, а не истина.** Совпадать с серверным
он не обязан и не будет: стандарт JavaScript не фиксирует точность `sin`, `cos`,
`atan2`, и у разных движков они различаются в последних битах, а за сотни
итераций расхождение разрастается. Истина всегда серверная; когда она приходит,
звёзды плавно переезжают на неё (`web/src/store.ts`, поле `prediction`).

Замеры на боевом сервере (1 ядро): 75 узлов — 0.64 с, 200 узлов — 2.2 с
полного пересчёта. Пересчёт запускается по изменению графа с дебаунсом
`LAYOUT_RECOMPUTE_DEBOUNCE_MS`, то есть несколько раз в сутки.

## Рендер

Один `requestAnimationFrame`-цикл, Canvas 2D, учёт `devicePixelRatio`.
Порядок отрисовки: фон → пыль → туманности → рёбра → венцы → ядра → подписи.

**Звезда — это её пламя.** Отдельного радиального ореола вокруг больше нет:
светится мягкая копия тех же языков (`soft*` в `tuning.flame`). Устройство
срисовано с `placidplace-sun-6751_128.gif` в корне репозитория — пропорции
брались замером кадров, а не на глаз.

- **Языков немного, и с размером звезды их число растёт еле-еле**: у звезды
  с одной связью двенадцать, у звезды с 25 связями пятнадцать-шестнадцать
  (`CORONA_TONGUES_AT`). Плотность на единицу окружности при этом падает,
  то есть у большой звезды язык шире — так и задумано.
- **Личный множитель числа языков** (`User.flame`, 0.55…1 с шагом 0.05)
  достаётся человеку при первом входе и закреплён за ним навсегда: два
  одинаковых по числу связей солнца всё равно горят по-своему.
- **Ядро** светлеет не к центру, а к краю: середина уходит в цвет звезды,
  кромка почти белая, сразу за краем короткий ореол в пятую часть радиуса.
- **Цвета по полу больше нет** — звёзды белые (см. отступления).
- **Связи скрыты целиком** (`EDGES_HIDDEN` в `renderer.ts`). Их огрызки
  у звезды складывались в несимметричное свечение: если соседи собрались
  слева, звезда «светила» налево. Код связей цел, возвращается одной строкой.
- **Глубина** — не WebGL, а параллакс: у каждой звезды своя `depth`, от неё
  зависят масштаб, яркость и скорость смещения при движении карты.
- **Резинки** (`canvas/wobble.ts`) — локальная физика перетаскивания звезды
  пальцем. На общую карту не влияет, после отпускания всё возвращается.

**Размер звезды** считается в `shared/layout/params.ts` — одной функцией
и для раскладки, и для клиента: раскладка разводит звёзды по этому же радиусу,
разъехаться этим двум формулам нельзя. Зависимость степенная: от 1 до 50
связей радиус растёт вчетверо с половиной, выше 70 связей рост придавлен
втрое — больше сотни знакомств набирают единицы.

**Производительность.** Венец не рисуется для звёзд мельче 7 px и не более
чем для 40 крупнейших за кадр; градиент ядра — только с 3 px. При отдалении
карты работа стремится к нулю сама.

Всё движение выключается при `prefers-reduced-motion: reduce`.

### Песочница

`web/sandbox.html` + `web/src/sandbox.ts` + `web/src/panel.ts` — отладочная
страница: полсотни звёзд от 1 до 50 связей на настоящем небе, без сервера,
базы и Telegram. Открывается через `npm run dev` в `web/` по адресу
<http://localhost:3006/galaxy/sandbox.html>; в сборку не попадает, потому что
vite собирает только `index.html`.

Справа панель ползунков: все величины вида звезды (`tuning` в `renderer.ts`)
правятся на лету, подобранное лежит в `localStorage`, кнопка «Скопировать»
отдаёт весь набор одним JSON — его и переносят в код как значения
по умолчанию. Так подбирались все нынешние числа; так же стоит делать впредь.

Адресом задаётся вид: `?star=37&zoom=14` — упереться в конкретную звезду.

## Отступления от ТЗ (все согласованы с заказчиком)

| Что | Почему |
| --- | --- |
| `server/src/` вместо `server/` в развёрнутом дереве | §2.4 и §15.1 противоречат друг другу; относительный путь до `shared/` должен совпадать локально и на сервере |
| PostgreSQL 16 из архива PGDG | В Ubuntu 20.04 штатно только 12, а основной репозиторий PGDG больше не собирает пакеты под focal |
| Охлаждение 0.995 вместо 0.985, α инкрементального 0.1 вместо 0.25, потолок итераций 800 вместо 200 | При числах из ТЗ симуляция замерзала, не дойдя до равновесия, и небо переезжало на 4% радиуса из-за одного нового человека |
| Снятие сноса центра масс в интеграторе | Без него система целиком уезжала на 250 единиц, а нормализация рывком тащила её обратно |
| Ранговая шкала целевого радиуса вместо второго min-max | На живом графе min-max сжимал всех, кроме главного хаба, к краю: небо получалось кольцом с пустой серединой |
| Бэкап раз в неделю, 4 копии (вместо суток и 14) | Просьба заказчика: лишние файлы и нагрузка |
| Расчёт раскладки ещё и на клиенте | Просьба заказчика: своё действие должно быть видно немедленно |
| Глубина, венец, резинки, изгиб связей | Новые пожелания заказчика сверх ТЗ |
| Цвет звезды не зависит от пола (§8.1) | Просьба заказчика: небо белое, цвет станет тем, что человек выберет себе сам |
| Радиальное свечение звезды убрано (§8.2) | Просьба заказчика: светиться должны сами языки пламени |
| Связи временно не рисуются | Просьба заказчика: огрызки связей делали свечение звезды несимметричным |
| Нижняя граница зума считается от размера неба | Диапазон 0.35–4 из ТЗ верен для неба размером с экран; на карте в 2000 единиц «целиком» — это меньше 0.35 |

## Команды

```bash
./deploy.sh                 собрать, залить, накатить миграции, перезапустить
./deploy.sh --setup         разовая настройка сервера (идемпотентна)
./deploy.sh --logs          живые логи
./deploy.sh --status        что крутится на сервере
./deploy.sh --fast          пропустить зависимости и миграции принудительно
./deploy.sh --full          выполнить их принудительно

cd server && npm test       32 теста: раскладка, аутентификация, связи, приглашения
```

Тяжёлые шаги деплоя выполняются, только если изменились `package-lock.json`,
`schema.prisma` или папка миграций — слепок лежит на сервере
в `/root/dev/galaxy/.deploy-state`. Обычный выкат — около 20 секунд.

На сервере, из `/root/dev/galaxy/dist`:

```bash
node server/src/lib/snapshot.js save <имя>      слепок графа
node server/src/lib/snapshot.js restore <имя>   вернуться к нему
node server/src/lib/snapshot.js list
node server/src/lib/seedDemo.js                 80 демо-звёзд
node server/src/lib/seedScenario.js             две компании с мостиком
```

Снимки — для опытов, не замена бэкапам: те снимает `pg_dump` по воскресеньям
в `/root/backups`.

## Тесты

`npm test` в `server/`. Семь тестов раскладки — самое важное: одиночная и
двойная звезда, монотонность «больше связей — ближе к центру», детерминизм,
стабильность при добавлении узла, выравнивание по Прокрусту, отсутствие
наложений. Плюс проверка подписи initData и поведение связей и приглашений
через настоящий HTTP и настоящую БД (`galaxy_test`).

Тесты с БД ходят в локальную `galaxy_test`; строку подключения можно
переопределить через `GALAXY_TEST_DATABASE_URL`.

## Секреты

Живут только в `/root/dev/galaxy/dist/.env` (права 600, root). В репозитории
их нет и быть не должно. Там: строка подключения к базе, токен бота, секрет
вебхука, секрет сессий, список админов. Потерять `SESSION_SECRET` — значит
разлогинить всех; потерять токен бота — переставить вебхук.
