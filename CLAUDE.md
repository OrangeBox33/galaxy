# Galaxy — памятка для будущих сессий

## Правило №1: согласование решений

Заказчик просит **согласовывать любое отступление от задуманного заранее**,
а не ставить перед фактом. Замеры и картинки вместо утверждений: почти каждое
решение здесь принималось по числам или по отрисованному предпросмотру.

## Правило №2: комментарии

Код показывает **как**; комментарий несёт только **почему**. По умолчанию
комментариев нет.

- Не пересказывать код, не подписывать очевидные константы, не ставить
  баннеры-разделители, не обращаться к ревьюеру («добавил», «раньше было»).
- Оставлять только то, чего в коде не прочитать: измеренные числа, причину
  неочевидного выбора, ловушку, инвариант, единицы измерения.
- Держать в минимуме слов: блок из пяти строк почти всегда сокращается до одной.
- Не восстанавливать удалённые комментарии при правке чужого кода.

То же про эту памятку: строка остаётся, только если без неё будут ошибки.

## Как устроено

| Слой       | Что использовано                                                 |
| ---------- | ---------------------------------------------------------------- |
| Клиент     | React 18 + TypeScript, Vite, zustand; рендер — Canvas 2D вручную |
| Сервер     | Node 22 + Express 4 + TypeScript, Prisma, PostgreSQL 16          |
| Процесс    | pm2, один инстанс `galaxy` на порту 3005                         |
| Веб-сервер | nginx проксирует `/galaxy/` на Node; статику раздаёт сам Node    |

Контейнеров нет. Запрещены и не используются: Next.js, Fastify, NestJS, Redis,
очереди, GraphQL, **zod и любые библиотеки схемной валидации**. PostgreSQL 16
стоит из архива PGDG: в Ubuntu 20.04 штатно только 12, а основной репозиторий
PGDG под focal больше не собирает.

`shared/` — общий код клиента и сервера: `config.ts` (BASE_PATH и константы,
один источник истины), `prng.ts`, `suggest.ts`, `layout/` (вся математика).
Остальное — по названиям каталогов.

## Вещи, которые нельзя ломать

1. **Подпуть `/galaxy`.** Задан один раз в `shared/config.ts` и протянут через
   `base` в Vite, роутер клиента, API-клиент, монтирование express-роутера,
   путь сессионной куки, адрес вебхука и раздачу аватарок. Захардкоженных
   `/api/...` быть не должно: они уведут в соседнее приложение домена.
2. **`proxy_pass` в nginx без завершающего слеша.** Со слешем nginx срежет
   префикс, и все маршруты отдадут 404.
3. **Ровно один инстанс pm2.** Таймер пересчёта раскладки и воркер рассылки
   держат состояние в памяти процесса.
4. **Каталог аватарок вне `dist`** (`/root/dev/galaxy/avatars`), иначе
   `rsync --delete` вычистит его при каждом деплое. То же про `.env`
   и `snapshots/`.
5. **Личность запроса берётся только из подписанной куки.** Клиентские id
   в теле запроса — это всегда цель действия, никогда не тот, кто действует.
6. **Прогретые аватарки и ассеты кешируются навсегда, `index.html` — никогда.**
7. **На сервере код лежит в `server/src/`, как и локально.** Относительный путь
   до `shared/` обязан совпадать в обоих местах.

## Раскладка

Ядро продукта. Считается на сервере, координаты пишутся в `User.x/y`,
клиент их только анимирует. Порядок: центральность → начальные позиции →
силовая симуляция → нормализация → выравнивание по Прокрусту → запись в БД.

**Коэффициент растяжения обязан переживать пересчёт.** Нормализация подгоняет
небо к `R_MAX`, а силы заданы в абсолютных единицах и сходятся к своему
размеру — при тесных компаниях он в разы меньше. Поэтому `computeLayout`
возвращает `scale`, runner хранит его в `LayoutState.params.scale` и подаёт
обратно через `previousScale`. Без этого пересчёт без единого изменения в графе
двигает медианную звезду на четверть радиуса неба.

- `centrality.ts` — ранговая шкала по числу связей; место звезды не определяет,
  нужна для порядка начальной расстановки и для глубины (параллакса). Именно
  ранговая, а не min-max: min-max сжимал всех, кроме главного хаба, к краю,
  и небо выходило кольцом с пустой серединой.
- `clusters.ts` — компоненты связности и сообщества (label propagation),
  детерминированно: обход по индексу, ничьи — за меньшей меткой.
- `normalize.ts` — масштаб по 65-му процентилю (`SCALE_PERCENTILE`): одиночки
  стоят на дальней орбите, мерить небо по ним — съёжить его интересную часть.
- `procrustes.ts` — поворот и отражение к предыдущей, чтобы небо не
  переворачивалось. `params.ts` — **все коэффициенты здесь**, с замерами.

**Два места выполнения.** На сервере (`layout/pool.ts`) — в `worker_thread`,
иначе сервис молчал бы секунду-две на каждом пересчёте. На клиенте
(`web/src/layout/worker.ts`) та же математика в Web Worker сразу после
действия человека.

**Числа интегратора подобраны замером, вниз не крутить.** Охлаждение 0.995,
α инкрементального пересчёта 0.1, потолок 800 итераций: при меньших значениях
симуляция замерзает не дойдя до равновесия, и небо переезжает на 4% радиуса
из-за одного нового человека. Снос центра масс снимается на каждом шаге —
без этого система уезжает на 250 единиц, а нормализация рывком тащит её назад.

**Клиентский расчёт — предположение, а не истина.** Совпадать с серверным он
не обязан: стандарт JavaScript не фиксирует точность `sin`, `cos`, `atan2`,
за сотни итераций расхождение разрастается. Когда приходит серверная истина,
звёзды плавно переезжают на неё (`web/src/store.ts`, поле `prediction`).

### Созвездия вместо каши

Место звезды значимо не в небе, а в её компании: кто знает своих лучше — тот
ближе к её середине. Требование желательное: расчёт обязан укладываться
в секунду-две. Отсюда два уровня, и силы каждого не мешают другому.

_Компании целиком_ (их ищет `clusters.ts`):

- `K_GROUP_RAD` — орбита компании по её размеру: суперкластер в середину,
  мелкие компании и одиночки к краю.
- `K_GROUP_REP` — компании расталкиваются как целые, за центроиды. Ручка
  «шире картина»: зазора внутри компании не трогает.

_Звёзды внутри компании_:

- `K_LOCAL` + `LOCAL_SPAN` — место по числу связей **внутри компании**. Связи
  наружу не в счёт: иначе мостик вытаскивал бы в середину того, кто в компании
  почти никого не знает.
- `K_CENTROID` — тяга к середине между своими друзьями, без длины покоя:
  с одним другом звезда встаёт вплотную к нему, с двумя — между ними.
- Пружины на связях, попарное отталкивание с надбавкой `REP_COMPONENT` для
  несвязанных с большинством, `K_RAD` — удержание неба в кадре.

Замеры на графе песочницы (100 звёзд, 218 связей): знакомые ближе незнакомых
в **7 раз**; «место в компании» (ранговая связь, −1 идеально) — **−0.6**;
появление человека сдвигает медианную звезду на **5–6 единиц** из 1400.

**По времени силы бесплатны**: O(n) на итерацию плюс O(k²) по компаниям. Узкое
место — попарное отталкивание O(n²) и разведение пересечений. Макбук: 100 звёзд
157 мс, 200 — 584 мс, 400 — 2.3 с. Боевой сервер (1 ядро) вчетверо медленнее:
75 узлов — 0.64 с, 200 — 2.2 с, то есть **бюджет упирается в ~200 звёзд**.
Пересчёт — по изменению графа с дебаунсом `LAYOUT_RECOMPUTE_DEBOUNCE_MS`.

## Рендер

Один `requestAnimationFrame`-цикл, Canvas 2D, учёт `devicePixelRatio`.
Порядок: фон → пыль → туманности → рёбра → венцы → ядра → подписи.

- **Связи на общей карте не рисуются** (`EDGES_HIDDEN`). **Вокруг звезды не
  должно быть ничего, кроме её пламени и ядра**: всё, что тянется наружу —
  огрызки связей, изгиб и колыхание линий, — читается как второе, чужое
  свечение поверх языков. Заводить заново не стоит. Связи выбранной звезды
  рисуются всегда, целиком и прямыми; остальной код связей цел.
- **Глубина** — не WebGL, а параллакс: своя `depth` задаёт масштаб, яркость
  и скорость смещения. **Резинки** (`canvas/wobble.ts`) — локальная физика
  перетаскивания пальцем, на общую карту не влияет.

**Куда садится новая звезда.** `freeSpot` (`shared/layout/index.ts`) идёт по
расходящейся спирали до первой свободной точки. Пришедший по личной ссылке
раскручивает спираль **от пригласившего**; пришедший сам — по всей площади
неба, со своей для каждого начальной точки.

**Размер звезды** — одной функцией в `params.ts` и для раскладки, и для
клиента: раскладка разводит звёзды по этому же радиусу, разъехаться формулам
нельзя. От 1 до 50 связей радиус растёт вчетверо с половиной, выше 70 рост
придавлен втрое.

**Зум.** Нижняя граница считается от размера неба, а не фиксированным числом,
и отдалять можно вчетверо дальше, чем «всё небо в экране» (`MIN_ZOOM_FACTOR`):
иначе небо упирается в края экрана и отъехать нельзя.

**Производительность.** Венец — только для звёзд крупнее 7 px и не более чем
для 40 за кадр; градиент ядра — с 3 px. Всё движение выключается при
`prefers-reduced-motion: reduce`.

### Песочницы

Три отладочных места, все без сервера, базы и Telegram.

- `sandbox/` в корне (в `.gitignore`) — одноразовые страницы для подбора
  анимаций: настоящий CSS из `styles.css`, разметка повторяется руками.
  Живут до переезда подобранного в код.
- `web/sandbox.html` (+ `sandbox.ts`, `panel.ts`) — вид звезды: полсотни звёзд
  от 1 до 50 связей на настоящем небе. `npm run dev` в `web/`,
  <http://localhost:3006/galaxy/sandbox.html>, в сборку не попадает. Справа
  ползунки всех величин `tuning` из `renderer.ts`, «Скопировать» отдаёт набор
  JSON'ом для переноса в код. Адресом задаётся вид: `?star=37&zoom=14`.
- `web/layout-sandbox.html` (+ `layoutSandbox.ts`, `layoutPanel.ts`,
  `layout/testGraph.ts`) — настоящий `computeLayout` на выдуманном графе из
  сотни звёзд той формы, где видно всё сразу. Две картинки: «Небо» (настоящий
  рендерер) и «Схема» (все связи, мостики отдельным цветом, раскраска по
  группам или сообществам). Строка замеров вместо ощущений: мс, число компаний,
  во сколько раз знакомые ближе незнакомых, «место в компании». Кнопки
  «+ звезда с 1 другом» считают инкрементально, как на бою.

**Ползунков раскладки намеренно семнадцать**: в панель попадает только то, чьё
влияние замерено заметным. Численная механика (`DT`, `D_MIN`, `GROUP_D_MIN`,
`SEPARATION_GAP`, `CLUSTER_ITERATIONS`) живёт константами в `simulate.ts` —
это не настройка вида, а то, что не даёт формулам взорваться.

## Возможные друзья

Окно в правом верхнем углу: до трёх карточек, каждая — человек в двух шагах
по графу.

- **Кого предлагать.** `shared/suggest.ts`: друзья друзей, с которыми я ещё
  не знаком. Порог `MIN_MUTUAL = 2` — с одним общим знакомым лез бы кто попало.
  Порядок (общие друзья → число связей → id) жёсткий: список не должен прыгать
  на каждом опросе графа.
- **Считается на клиенте**: весь граф уже пришёл в `/api/graph`, поэтому
  подсказки обновляются сразу после своего же «Связать».
- **Отказы — на сервере.** `SuggestionDismissal`, `POST
/api/suggestions/dismiss`, список в `graph.dismissed`. «Нет» бессрочно
  и односторонне: второй по-прежнему видит первого.
- **Анимация** (`components/Suggestions.tsx` + `.suggest*` в `styles.css`):
  слот держит место в стопке, содержимое — прилёт снизу (450 мс) и уход.
  «Связать» — вдох, побеление, схлопывание в точку у кнопки (360 мс), дальше
  искра летит к звезде человека; «Нет» — угасание за 340 мс.
- **Искра живёт в `body` с `position: fixed`** (`.suggest__seed`): у карточки
  `overflow: hidden`, у неба своя канва, перелететь внутри React-дерева нечем.
  Координаты даёт `screenOf(id)`; звезда за краем — искра гаснет у кромки.
  Уходящая карточка держит место в стопке до конца анимации: иначе нижняя
  переезжает под вспышку и подсвечивается чужая. **Шаг стопки 72 px записан
  дважды** — в `Suggestions.tsx` и в CSS.
- **Карточка живёт своей копией данных.** Иначе исчезает под пальцем: своя же
  новая связь меняет число общих друзей у соседей, и кто-то выпадает
  за `MIN_MUTUAL`.

## Приглашения

**У человека одна ссылка, и она постоянная.** `User.inviteToken` выдаётся при
первом обращении и больше не меняется; `https://t.me/<бот>?startapp=<токен>`.
Токен — три знака, цифры и строчная латиница (`TOKEN_LENGTH`
в `server/src/lib/inviteLink.ts`).

Кто угодно и сколько угодно раз: каждый, кто откроет и войдёт, получает связь
с хозяином ссылки (`linkByPersonalToken`). Повторный приход ничего не делает,
своя ссылка петли не создаёт, ссылка заблокированного не связывает,
`MAX_LINKS_PER_USER` действует и здесь.

**Тусклых точек приглашений на небе нет** (`INVITES_HIDDEN` в `renderer.ts` —
рисование и попадание пальцем): точка зажигалась бы на создании ссылки, до
того как её кому-то отправили.

Механика одноразовых приглашений цела (`Invite`, `/api/invites`,
`graph.pending`, `drawInvites`, карточка в `StarCard`), старые ссылки работают:
`acceptInvite` сначала ищет постоянный токен, потом идёт этим путём.

**Узнать, кому отправили ссылку, Telegram не даёт.** Проверялось:
`WebApp.shareMessage` возвращает только «отправлено» без адресата,
`chosen_inline_result` — отправителя, а кнопка `KeyboardButtonRequestUsers`
работает лишь в чате с ботом. Искать обход заново не стоит.

## Команды

```bash
./deploy.sh                 собрать, залить, накатить миграции, перезапустить
./deploy.sh --setup         разовая настройка сервера (идемпотентна)
./deploy.sh --logs          живые логи
./deploy.sh --status        что крутится на сервере
./deploy.sh --fast          пропустить зависимости и миграции принудительно
./deploy.sh --full          выполнить их принудительно

cd server && npm test       52 теста
```

Тяжёлые шаги идут, только если изменились `package-lock.json`, `schema.prisma`
или миграции (слепок на сервере в `.deploy-state`); обычный выкат — 20 секунд.

**node стоит через nvm, а неинтерактивный ssh не читает профиль**, поэтому
снаружи каждой команде нужна преамбула — та же, что в `deploy.sh:46`:

```bash
ssh root@193.124.203.221 'export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; \
  cd /root/dev/galaxy/dist && node server/src/lib/snapshot.js list'
```

Изнутри сервера, из `/root/dev/galaxy/dist`, хватает самих команд:

```bash
node server/src/lib/snapshot.js save|restore|list <имя>   слепки графа
node server/src/lib/seedDemo.js                          80 демо-звёзд
node server/src/lib/seedScenario.js                      две компании с мостиком
node server/src/lib/unlinkAll.js who                     id и число связей
node server/src/lib/unlinkAll.js <id> [--dry]            развязать человека
```

Снимки — для опытов, не замена бэкапам: те снимает `pg_dump` по воскресеньям
в `/root/backups`, хранятся четыре последних.

## Тесты

`npm test` в `server/`. Семь тестов раскладки — самое важное: одиночная и
двойная звезда, место в компании (компания из 50, двое знают в ней всех —
эти двое обязаны стоять ближе к её середине), детерминизм, стабильность при
добавлении узла, Прокруст, отсутствие наложений. Плюс подпись initData и
поведение связей и приглашений через настоящий HTTP и БД `galaxy_test`
(строка подключения — `GALAXY_TEST_DATABASE_URL`).

## Секреты

Живут только в `/root/dev/galaxy/dist/.env` (права 600, root), в репозитории
их нет и быть не должно: строка подключения к базе, токен бота, секрет вебхука,
секрет сессий, список админов. Потерять `SESSION_SECRET` — разлогинить всех;
потерять токен бота — переставить вебхук.
