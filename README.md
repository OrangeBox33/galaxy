# Galaxy

Карта знакомств в виде звёздного неба. Каждый участник — светящаяся звезда,
подтверждённое знакомство — тонкая линия. Чем больше связей у человека, тем ближе
его звезда к центру карты.

Вход только через Telegram Mini App; id пользователя в системе равен его Telegram id.
Адрес: <https://kvadratnikitosa.ru/galaxy>

## Устройство

```
galaxy/
  shared/config.ts      BASE_PATH и общие константы — один источник истины для клиента и сервера
  server/
    src/
      index.ts          старт процесса
      app.ts            сборка express-приложения (отдельно — чтобы поднимать в тестах)
      env.ts            чтение переменных окружения руками, без библиотек
      auth/             проверка initData, сессии, middleware
      routes/           auth, me, graph, invites, links, admin, bot, static
      layout/           центральность, симуляция, Прокруст, пересчёт
      avatars/          очередь загрузки аватарок
      bot/              Bot API, воркер рассылки, настройка вебхука
      lib/              валидация, имена, ГПСЧ, лимиты, сид-скрипт
    prisma/             схема и миграции
  web/
    src/
      canvas/           рендер неба: камера, спрайты свечения, сцена, хит-тест
      screens/          Sky, Admin
      components/       карточка звезды, панели профиля и приглашения
      api/              типизированный клиент; URL собирается только здесь
  deploy/               ecosystem.config.cjs, фрагмент nginx, скрипты сервера
  deploy.sh             сборка, заливка, миграции, перезапуск
```

Ключевые решения, о которых стоит знать до правок:

- **Приложение живёт на подпути `/galaxy`.** Базовый путь задан один раз в
  `shared/config.ts` и протянут через vite `base`, роутер клиента, API-клиент,
  монтирование express-роутера, путь сессионной куки и адрес вебхука.
  Захардкоженных `/api/...` в коде быть не должно.
- **Статику раздаёт Node, не nginx** — в nginx ровно одна запись `location /galaxy/`.
- **Инстанс ровно один.** Таймер пересчёта раскладки и воркер рассылки держат
  состояние в памяти процесса; при нескольких копиях они начнут дублировать работу.
- **zod и прочие библиотеки схемной валидации не используются.** Тела запросов
  разбираются функциями из `server/src/lib/validate.ts`, поле за полем.

## Локальная разработка

Нужны Node 22 и PostgreSQL (локально — для тестов и `prisma migrate dev`).

```bash
cd server && npm install
cd ../web && npm install
```

Тестовая база (создаётся один раз):

```bash
createdb galaxy_test
cd server
DATABASE_URL="postgresql://$(whoami)@127.0.0.1:5432/galaxy_test" npx prisma migrate deploy
npm test
```

По умолчанию тесты ходят в `galaxy_test` от имени текущего пользователя — так базу
заводит Homebrew. Другую строку подключения можно задать переменной
`GALAXY_TEST_DATABASE_URL`.

Сервер локально запускать не обязательно: правки проверяются выкатом на прод
(`./deploy.sh`), это занимает около минуты. Клиент можно крутить отдельно
(`cd web && npm run dev`), но вход через Telegram в dev-режиме не работает —
`initData` вне Telegram не подделать.

### Миграции: локально и на проде — по-разному

- **Локально** новая миграция создаётся через `npx prisma migrate dev --name <имя>`.
  Этой команде нужна теневая база, поэтому локальная роль должна иметь `CREATEDB`.
- **На проде** выполняется только `npx prisma migrate deploy` — ему достаточно прав
  владельца базы, теневая база не нужна. Атрибут `CREATEDB` роли `galaxy` на сервере
  не выдан намеренно. `migrate dev` и `db push` на проде не запускать никогда.

Первая миграция (`prisma/migrations/0_init`) сгенерирована без подключения к БД:

```bash
npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script
```

## Сервер

VPS `root@193.124.203.221`, Ubuntu 20.04. Рядом живут два чужих проекта, которые мы
не трогаем: `kvadrat` (порт 3500, корень домена) и `textbin` (порт 8090, `/bankiru`).
Наш процесс — `galaxy` на порту 3005.

Node и pm2 поставлены через nvm, а неинтерактивный ssh не читает профиль, поэтому
каждая удалённая команда начинается с подгрузки nvm:

```bash
export NVM_DIR="$HOME/.nvm"; [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh";
```

### Разовая настройка

```bash
./deploy.sh --setup
```

Скрипт идемпотентен и делает:

1. ставит pm2, если его нет, и включает автозапуск после ребута;
2. создаёт `/root/dev/galaxy/{avatars,dist}` и `/root/backups`;
3. ставит PostgreSQL 16 и заводит роль и базу `galaxy`;
4. проверяет, что кластер в UTF-8 и слушает только localhost;
5. кладёт `backup.sh` и добавляет его в крон.

PostgreSQL ставится **из архива PGDG** (`apt-archive.postgresql.org`): в штатном
репозитории Ubuntu 20.04 есть только версия 12, а основной репозиторий PGDG больше
не собирает пакеты под focal — эта версия системы отжила свой срок в мае 2025.
При переезде на Ubuntu 24 достаточно поменять в `deploy/setup-server.sh` хост
и кодовое имя репозитория на `noble-pgdg` и обновить пакеты.

Кластер общесерверный: у каждого проекта своя роль и своя база, приложение никогда
не подключается суперпользователем `postgres`, глобальные настройки не трогает.

### `.env`

Создаётся на сервере вручную один раз, лежит в `/root/dev/galaxy/dist/.env`,
в rsync не участвует и деплоем не перетирается.

```
DATABASE_URL=postgresql://galaxy:<пароль>@127.0.0.1:5432/galaxy
PORT=3005
PUBLIC_BASE_URL=https://kvadratnikitosa.ru/galaxy
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_BOT_USERNAME=<имя бота без @>
TELEGRAM_WEBHOOK_SECRET=<openssl rand -hex 32>
SESSION_SECRET=<openssl rand -hex 32>
ADMIN_TELEGRAM_IDS=<id через запятую>
AVATAR_DIR=/root/dev/galaxy/avatars
LAYOUT_RECOMPUTE_DEBOUNCE_MS=4000
```

Каталог аватарок лежит **рядом с `dist`, а не внутри**: иначе `rsync --delete`
вычищал бы загруженные аватарки при каждом деплое.

### nginx

Фрагмент лежит в `deploy/nginx.galaxy.conf` и уже вставлен в
`/etc/nginx/sites-available/kvadratnikitosa.ru`. Важное:

- `proxy_pass http://127.0.0.1:3005;` **без завершающего слеша** — так nginx передаёт
  исходный URI целиком, вместе с префиксом `/galaxy`, которого и ждёт Express.
  Со слешем префикс будет срезан, и все маршруты отдадут 404.
- В объемлющем `server {}` не должно быть `X-Frame-Options: DENY` или
  `frame-ancestors`, запрещающих `https://web.telegram.org`, — иначе Mini App
  не откроется в веб-клиенте Telegram.

### Telegram

```bash
cd server && npm run setup:bot
```

Скрипт ставит вебхук на `<PUBLIC_BASE_URL>/tg/webhook/<TELEGRAM_WEBHOOK_SECRET>`
и показывает, что об этом думает Telegram. Отдельно, руками в BotFather:
`/mybots` → бот → **Bot Settings → Configure Mini App → Enable**, URL
`https://kvadratnikitosa.ru/galaxy`. Без включённого Mini App ссылки-приглашения
вида `t.me/<бот>?startapp=<токен>` не сработают.

## Деплой

```bash
./deploy.sh              собрать клиент и сервер, залить, накатить миграции, перезапустить
./deploy.sh --setup      разовая настройка сервера
./deploy.sh --migrate    только миграции
./deploy.sh --logs       живые логи
./deploy.sh --status     что крутится на сервере
./deploy.sh --restart    перезапуск без сборки
./deploy.sh --no-build   залить уже собранное
./deploy.sh --fast       не ставить зависимости и не трогать миграции
./deploy.sh --full       поставить зависимости и накатить миграции принудительно
./deploy.sh --dry-run    показать, что бы залилось
```

Собирается всё локально, на сервер уезжает готовый `dist`. Миграции идут строго
до перезапуска: если они не легли, деплой прерывается, pm2 не трогается
и продолжает работать прежняя версия.

Тяжёлые шаги на сервере выполняются, только если для них что-то изменилось:

| шаг | когда выполняется |
| --- | --- |
| `npm install --omit=dev` (и `prisma generate` из `postinstall`) | изменился `package-lock.json` |
| `npx prisma generate` | изменился `schema.prisma`, а зависимости — нет |
| `npx prisma migrate deploy` | изменилось содержимое `prisma/migrations` |

Контрольные суммы этих файлов хранятся на сервере в `/root/dev/galaxy/.deploy-state`
— вне `dist`, поэтому rsync их не трогает. Обычный выкат правки в коде занимает
около двадцати секунд вместо сорока. Пропустить проверку можно флагом `--fast`,
выполнить всё принудительно — `--full`.

Из rsync исключены и не удаляются: `node_modules`, `.env`, `.DS_Store`.

## Резервные копии

`/root/dev/galaxy/backup.sh` по воскресеньям в 4:00 делает `pg_dump -Fc` базы `galaxy`
в `/root/backups`, храня четыре последних копии. Дамп снимается по нашей базе,
а не по всему кластеру: бэкапы будущих проектов должны быть независимы.

Восстановление:

```bash
# 1. Погасить приложение, чтобы оно не писало в базу во время восстановления.
export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; pm2 stop galaxy

# 2. Пересоздать базу пустой.
sudo -u postgres psql -c "DROP DATABASE galaxy;"
sudo -u postgres psql -c "CREATE DATABASE galaxy OWNER galaxy ENCODING 'UTF8';"

# 3. Залить дамп.
pg_restore -d "postgresql://galaxy:<пароль>@127.0.0.1:5432/galaxy" \
  --no-owner /root/backups/galaxy-<дата>.dump

# 4. Поднять обратно.
pm2 start galaxy
```

Аватарки в дампе не лежат — они файлы в `/root/dev/galaxy/avatars`. Если потерялись,
ничего страшного: каждый войдёт и его аватарка подтянется заново.

## Раскладка

Координаты считает сервер и пишет в `User.x/y`; клиент только анимирует небольшие
колебания вокруг них. Пересчёт запускается через `LAYOUT_RECOMPUTE_DEBOUNCE_MS`
после последнего изменения графа; из админки можно запустить его руками в двух
режимах — «досчитать» (от сохранённых мест) и «переложить заново» (с нуля).

Все коэффициенты собраны в `server/src/layout/params.ts` с комментариями. Отличия
от чисел в ТЗ помечены там же прямо в коде — каждое из них согласовано и объяснено:
охлаждение, стартовая температура инкрементального пересчёта, потолок итераций
и ранговая шкала целевого радиуса.

Тесты раскладки (`npm test`) проверяют одиночную и двойную звезду, монотонность
«больше связей — ближе к центру», детерминизм, стабильность при добавлении узла,
выравнивание по Прокрусту и отсутствие наложений.
